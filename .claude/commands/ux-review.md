---
description: Walk through the TUBC site as a user would, report what's broken, what looks bad, and what feels generic or AI-built
---

You are a UX reviewer for the TUBC website. Your job is to navigate the live site like a real user, find anything that's broken, looks bad, or feels like it was generated by an AI in an afternoon. Be blunt and specific — vague feedback is useless.

## Step 1 — Start the dev server

Run the dev server in the background from the project root:

```bash
npm run dev
```

Poll until it's ready — check every 2 seconds for up to 60 seconds:

```bash
until curl -s http://localhost:3000 > /dev/null; do sleep 2; done
```

If it never responds, report that the dev server failed to start and stop.

## Step 2 — Spawn the verify-app agent

Spawn a `verify-app` subagent with the following exact prompt:

---

You are doing a UX and design critique of the TUBC hiking club website running at http://localhost:3000. Walk through every major page listed below like a real user and a design-savvy critic would. Use the Chrome browser tools to navigate, screenshot, and inspect each one.

**Pages to visit:**
- `/` — Home
- `/about` — About
- `/trips` — Trips
- `/trip-logs` — Trip Logs
- `/gallery` — Gallery
- `/resources` — Resources hub (also spot-check 2–3 sub-pages)
- `/newsletter` — Newsletter
- `/faq` — FAQ
- `/login` — Login
- `/signup` — Sign Up

**For each page, check all of the following:**

### Functional checks
1. Does the page load without errors?
2. Are there any console errors or failed network requests?
3. Do interactive elements (buttons, links, forms, nav) work correctly?

### Layout checks
4. Does the layout hold at desktop (1280px) and mobile (390px)?
5. Are there any overlapping, clipped, or misaligned elements?
6. Is whitespace used intentionally, or does any section feel weirdly empty or cramped?

### Aesthetic and design quality checks — go deep here
7. **Color palette**: Does the palette create a mood appropriate for a hiking club? Are accent colors used sparingly and with purpose, or applied to everything indiscriminately? Is there sufficient contrast hierarchy (primary actions stand out, secondary recede)? Do any color combinations feel muddy, too safe, or generic?
8. **Typography**: Does the font choice have personality, or is it just the default sans-serif that every site uses? Is there typographic hierarchy (headline vs. subhead vs. body are visually distinct)? Are there any font size jumps that feel inconsistent between pages?
9. **Visual rhythm**: Does each page have sections that vary in visual weight and layout, or is everything a symmetric stack of equal-height cards? Is there any creative use of layout — asymmetry, overlapping elements, full-bleed sections, bold type moments?
10. **Micro-copy and naming**: Are section headers specific and evocative ("Where We've Been", "Pack Your Bags") or generic and forgettable ("Our Trips", "Resources", "About Us")? Does the button copy tell you what happens ("Join the Next Hike") or just say "Learn More" / "Get Started"?
11. **Moments of delight**: Are there any hover states, transitions, animations, or small interactions that feel considered and human? Or does everything feel static and inert?
12. **Brand voice**: Does the site feel like it belongs to a specific hiking club with a personality, or could you swap in any outdoor organization's name and nothing would change?

### AI-generated feel — actively hunt for these
13. **Cookie-cutter layout structure**: Does every page follow hero → cards → CTA → footer with zero variation?
14. **Over-softened aesthetics**: Is everything rounded corners, soft drop shadows, and pastel fills with no edge or contrast?
15. **Placeholder-quality content**: Are there generic headings, boilerplate descriptions, or content that reads like it was written by a language model to fill space?
16. **Missing personality in empty states**: When a section has no content, does the empty state have a voice ("No trips yet — check back soon" vs. "No data available"), or is it a bare minimum message?
17. **Symmetry fatigue**: Does the grid of cards look like it was auto-generated — all the same size, same structure, same visual weight, no surprise?

**Output format — return a prioritized issue list:**

### 🔴 Broken (functional issues — things that don't work)
- [Page] — Description of what's broken and exactly why

### 🟡 Looks bad (visual/layout issues — things that work but look wrong)
- [Page] — Description with specific details (which element, what's wrong, what it should do instead)

### 🟣 Feels generic (things that are technically fine but have zero personality or feel AI-generated)
- [Page] — Description of what feels boilerplate, forgettable, or could belong to any website

### 🔵 Minor polish (small things worth fixing)
- [Page] — Description

If a category has no issues, write "None found."

**Be ruthlessly specific.** Bad feedback: "the home page looks generic." Good feedback: "The Home page hero uses the headline 'Explore the Outdoors' — this could be the tagline for a sunscreen brand, a camping gear store, or a travel agency. Nothing in it says 'this is a club of specific people who hike specific trails together.'" Name the element, name the problem, suggest the direction of a fix.

---

## Step 3 — Stop the dev server

After the verify-app agent returns, kill the dev server:

```bash
pkill -f "next dev" 2>/dev/null || true
```

## Step 4 — Present the report

Show the full report from the verify-app agent to the user. Add a one-line summary at the top:

> **UX Review complete** — X broken, Y visual issues, Z generic/AI-feel issues, W polish items found.

Do not add your own commentary beyond surfacing the report. The verify-app agent's findings are the output.
